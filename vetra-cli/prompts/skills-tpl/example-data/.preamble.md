**Why.** At the first launch the live product opens on its own drive, filled
once with a small starter set of example documents, so the first visitor
never sees an empty product. You write that starter set in the Tests step;
`reactor-project-check` with `tests: true` checks it as part of the preview
smoke check, and `done TESTS` is refused until it passes.

**What to write.** One file per document type at the reactor project's root:
`<project>/seed/<document-type-name>.json` (e.g. `seed/todo-list.json`).
Take the documents from your preview sample data — the same realistic
content, 1–3 documents per type (at most 10).

    {
      "documentType": "acme/todo-list",
      "documents": [
        {
          "name": "Example — delete me: Weekend chores",
          "actions": [
            { "type": "ADD_TODO", "input": { "id": "todo-1", "title": "Buy milk" } },
            { "type": "ADD_TODO", "input": { "id": "todo-2", "title": "Water plants" } },
            { "type": "COMPLETE_TODO", "input": { "id": "todo-1" } }
          ]
        }
      ]
    }

**Rules the check enforces.**
- `documentType` is a document type this project defines (its model id).
- Every `name` starts with `Example — delete me` (em dash), optionally
  followed by `: <title>`.
- `actions` are the model's own operations, in the order a user would do
  them: `type` is the operation name, `input` matches its input type
  exactly (required fields present, enum values spelled as in the schema,
  no unknown fields). `scope` may be left out.
- Ids and dates come from the input like in any dispatch: write fixed ids
  (`todo-1`) and fixed ISO dates; they only need to be unique within the
  document.
- At most 100 actions per document. Skip document types that only make
  sense inside another document.

**When it fails.** The check names the document and the problem (for
example `action 2 ADD_TODO: Field "title" of required type "String!" was not
provided`). Fix the file and run `reactor-project-check` with `tests: true`
again. When you change a model later, update its seed file in the same
change — the check runs against the current models.

The drive and its examples are created only at the first launch; later
launches never touch them, and the product's users delete the examples
themselves.
