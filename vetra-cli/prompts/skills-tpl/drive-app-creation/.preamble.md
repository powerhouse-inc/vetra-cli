A drive app is a React component bound to a drive (not a document) that
renders a custom UI at the root of that drive — a dashboard, kanban board,
IDE-like surface, etc. The spec lives at
`<project>/specs/apps/<app>.app.phd` and is edited through `spec-*` tools;
the generated code under `<project>/editors/<appId>/` is not the source of
truth.

## Required reading

- **Before `spec-update` on an app spec**, `skill_read`
  `00.check-prerequisites`. It covers the app-status enum
  (**`CONFIRMED` | `DRAFT`** — there is no `ACTIVE`), how
  `ADD_DOCUMENT_TYPE` / `SET_DOCUMENT_TYPES` declare which document types
  the app surfaces, and what needs to exist before the app will preview.
- **Before writing component code**, `skill_read`
  `01.write-app-implementation`. Covers the two rendering patterns
  (Connect-navigation vs. in-place), the drive introspection API,
  persisting selection in the URL, and which files are safe to edit.
- **Before previewing**, `skill_read` `02.preview-app`. Apps preview as a
  **drive** (not a document) — the flow creates a preview drive bound to
  the app, populates it with sample documents, then shows the drive root.

## Authoring flow

1. `spec-create --type powerhouse/app --name "<App Name>"`
2. `spec-update` with `SET_APP_NAME`, `ADD_DOCUMENT_TYPE` (×N),
   `SET_DRAG_AND_DROP_ENABLED`, `SET_APP_STATUS` → `CONFIRMED`.
3. `spec-generate` — scaffolds `<project>/editors/<appId>/` with a
   `DriveExplorer` boilerplate.
4. **Customize `editor.tsx`** — replace the boilerplate with real UI.
   `editor.tsx` is preserved by codegen once customized; add new
   components alongside it rather than editing the regenerated
   `components/*`, `module.ts`, `config.ts`.

## Gate before preview

`spec-preview-show` against an app that hasn't been customized renders
the generic `DriveExplorer`. Before preview, confirm:
- `spec-generate` ran clean.
- `<project>/editors/<appId>/editor.tsx` contains real UI (not just the
  default `DriveExplorer` pass-through).
- `powerhouse.manifest.json` `apps[]` lists the app with the correct `id`.

## Never

- Hand-edit `<project>/editors/<appId>/gen/` — regeneration overwrites.
- Hand-edit `components/*`, `module.ts`, `config.ts` under the app dir —
  these regenerate on each `spec-generate`. Add NEW component files
  instead.
- Restart the reactor after editing component source. Vite HMR is on.
