# DEP.00 Preflight and package identity

## DEP.00.1 Confirm the project type-checks

- Run `reactor-project-check` (pass `--name <project>` when the workdir isn't
  the project). Fix every error before going further — deploying a broken build
  wastes a publish and an environment slot.
- If the errors live in a document model or editor, that's a handoff signal, not
  something to fix from here — see `05.troubleshoot-and-handoff`.

## DEP.00.2 Identify the package

- Read `<project>/package.json` for `name` and `version`. This `name@version` is
  exactly what you publish and then install into the environment — the two must
  match, or the env installs a different build than you shipped.
- If `package.json` has no `name`, the project isn't publishable; stop and tell
  the user.

## DEP.00.3 Pin the target environment

- Note which environment this deploy targets — a name/subdomain the user gave,
  or "create a new one". You resolve it in `02.environment`; capturing intent now
  keeps the later reuse-vs-create decision honest.
