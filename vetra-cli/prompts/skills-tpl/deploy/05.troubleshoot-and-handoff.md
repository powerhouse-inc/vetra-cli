# DEP.05 Troubleshoot and hand off

## DEP.05.1 Build / type errors

- `reactor-project-check` lists the diagnostics. If they're in hand-written code
  you own, fix and re-run.
- If the error is in a **document model** (state schema, operations, reducers),
  hand off to the document-model subagent with the failing file + message. An
  **editor** component → the editor subagent. A **drive app** → the app subagent.
  Don't fix document-model/editor/app internals from here — those subagents own
  that surface and have the skills for it.

## DEP.05.2 Publish / auth errors

- "Not authenticated" / 401 / 403 from publish or `reactor-project-publish-status`
  → the registry needs login. Tell the user to `npm login --registry <url>` or
  set `config.registryUsername` / `config.registryPassword`, then retry.
- "version already exists" → you tried to republish a published version; bump the
  version (DEP.01.2) and publish the new one.

## DEP.05.3 DEPLOYMENT_FAILED

- Read the environment (`deploy-environment-get --name <env>`) for the failure
  detail. Common causes: the installed `name@version` isn't actually in the
  registry (re-check with `reactor-project-publish-status`), or a required
  service is disabled.
- Fix the root cause, then re-approve. If the root cause is a document model /
  editor / app, hand off as in DEP.05.1.

## DEP.05.4 When in doubt, surface it

- If a step is mocked, or a check returns "unknown", say so and ask the user
  rather than presenting a guess as fact. A deploy reported as live when it isn't
  is the worst failure mode.
