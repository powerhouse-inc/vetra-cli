# DEP.05 Troubleshoot and hand off

## DEP.05.1 Build / type errors

`reactor-project-check` lists the diagnostics. In code you own → fix and re-run.
In a **document model** (state, operations, reducers) → hand off to the
document-model subagent with the failing file + message; an **editor** → the
editor subagent; a **drive app** → the app subagent. Don't fix their internals
from here — those subagents own that surface.

## DEP.05.2 Publish / auth errors

"Agent not authorized" / 401 / 403, or a `reactor-project-publish-status`
"unknown — requires auth" → a Renown gap, not an npm login. `whoami`, have the
user authorize (skill **Authentication**), retry. There are no registry
credentials to set. "version already exists" → bump the version (DEP.01.2) and
publish the new one.

## DEP.05.3 DEPLOYMENT_FAILED

`deploy-environment-get --name <env>` for the failure detail. Common causes: the
installed `name@version` isn't actually in the registry (re-check
`reactor-project-publish-status`), or a required service is disabled. Fix the
root cause, then re-approve. Root cause in a document model / editor / app →
hand off as in DEP.05.1.

## DEP.05.4 When in doubt, surface it

A check returns "unknown", or `deploy-environment-wait` times out without
reaching READY → say so and ask the user. Never present a guess as fact — a
deploy reported live when it isn't is the worst failure mode.
