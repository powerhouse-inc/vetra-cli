# DEP.03 Install and go live

## DEP.03.1 Install the published package

- Nothing to install if the env already has this exact `name@version` with no
  unpublished changes (DEP.00.4) — skip to the links (DEP.03.3).
- `deploy-environment-update --name <env> --addPackage <name>@<version>` — the
  exact version you confirmed published in DEP.01. An unpublished version fails.
- Confirm: `deploy-environment-get --name <env> --filter $.packages`.

## DEP.03.2 Approve and wait

- Moving changes live is an approval: `deploy-environment-update --name <env>
  --transition CHANGES_APPROVED`. State machine: DRAFT → CHANGES_PENDING →
  CHANGES_APPROVED → CHANGES_PUSHED → DEPLOYING → **READY** (failure:
  DEPLOYMENT_FAILED).
- Then call `deploy-environment-wait --name <env>` **once** — it blocks (polls
  every 5s, up to 30s; `--timeout 60` for slower deploys) until the status
  settles to READY or DEPLOYMENT_FAILED. **Don't** poll `deploy-environment-get`
  in a loop; if wait reports still deploying, call it again. DEPLOYMENT_FAILED →
  `05.troubleshoot-and-handoff`.
- TERMINATING / DESTROYED / ARCHIVED are terminal — you can't deploy into them.

## DEP.03.3 Return the links

Once READY, give the user the URLs (with the env's `subdomain`):

- Cloud page: `https://staging.vetra.io/user/environments/<environment-id>`
- Connect: `https://connect.<subdomain>.vetra.io`
- Switchboard GraphQL: `https://switchboard.<subdomain>.vetra.io/graphql`
- Fusion (if enabled): `https://fusion.<subdomain>.vetra.io`

`deploy-environment-get` already renders these hosts — prefer quoting its output
over hand-building URLs.
