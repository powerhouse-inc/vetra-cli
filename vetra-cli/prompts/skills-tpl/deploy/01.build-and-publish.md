# DEP.01 Build and publish the package

## DEP.01.1 Build

- Run `reactor-project-build`. It produces the Node + browser bundles the cloud
  loads. If it fails, stop and read `05.troubleshoot-and-handoff`.

## DEP.01.2 Decide whether to publish (publish-if-changed)

Publish only when there are unpublished changes; otherwise reuse the last
publish. Use `reactor-project-publish-status` as the authoritative signal:

- Run `reactor-project-publish-status`. Pass `--registry <env registry>` so the
  check matches where the environment installs from (the env's
  `defaultPackageRegistry` — see `02.environment`).
- **Published** → the current `name@version` is already in the registry. If you
  changed the project since, **bump the version** and publish the new one. If
  nothing changed, **reuse** it — do not republish.
- **Not published** → there are unpublished changes (or it was never published);
  publish this version.
- **Unknown** (auth/network) → don't guess. Either the registry was unreachable
  or it requires an authorization the agent doesn't have. Confirm with `whoami`;
  if not authorized, have the user authorize the agent (skill **Authentication**
  section), then retry. Otherwise report the registry was unreachable and stop
  here.

## DEP.01.3 Publish

- Run `reactor-project-publish --registry <env registry>`. It builds (unless
  `--skipBuild`), mints a short-lived registry token from the agent's Renown
  authorization, and publishes — there are **no** username/password flags or
  credentials to set. If the agent isn't authorized it returns "Agent not
  authorized"; have the user authorize (skill **Authentication** section), then
  retry.
- Useful flags: `--version <new>` bumps `package.json` before publishing;
  `--tag <dist-tag>`; `--dryRun` validates without publishing; `--skipBuild` if
  you already built in DEP.01.1.
- Re-run `reactor-project-publish-status` to confirm the version is now published
  before touching the environment. An install of an unpublished version fails on
  a real cloud.
