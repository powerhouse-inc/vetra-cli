# DEP.01 Build and publish

## DEP.01.1 Build

`reactor-project-build` produces the Node + browser bundles the cloud loads.
Fails → `05.troubleshoot-and-handoff`.

## DEP.01.2 Publish only if changed

`reactor-project-publish-status --registry <env registry>` is the authoritative
signal — pass the env's `defaultPackageRegistry` so the check matches where the
env installs from:

- **Published** → the current `name@version` is in the registry. Changed it
  since? bump the version and publish the new one. Nothing changed? reuse it —
  don't republish.
- **Not published** → publish this version.
- **Unknown** (auth/network) → don't guess. `whoami`; if not authorized, have the
  user authorize (skill **Authentication**), then retry; otherwise report the
  registry unreachable and stop.

## DEP.01.3 Publish

`reactor-project-publish --registry <env registry>` builds (unless `--skipBuild`),
mints a short-lived registry token from your Renown authorization, and publishes
— there are **no** credentials to set. "Agent not authorized" → authorize, then
retry. Flags: `--version <new>` (bumps `package.json` first), `--tag <dist-tag>`,
`--dryRun`, `--skipBuild`.

Re-run `reactor-project-publish-status` to confirm the version is published
before touching the environment — installing an unpublished version fails on a
real cloud.
