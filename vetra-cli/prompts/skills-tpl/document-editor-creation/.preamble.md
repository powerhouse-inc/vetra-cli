A document editor is a React component bound to a specific document
type. The spec lives at `<project>/specs/editors/<editor>.editor.phd`
and is edited through `spec-*` tools; the generated code under
`<project>/editors/` is not the source of truth.

## Required reading

- **Before `spec-update` on an editor spec**, `skill_read`
  `00.check-prerequisites`. It covers the editor-status enum
  (**`CONFIRMED` | `DRAFT`** — there is no `ACTIVE`), how
  `ADD_DOCUMENT_TYPE` binds an editor to a document model, and what
  needs to exist on the document-model side before the editor will
  preview correctly.
- **Before writing component code**, `skill_read`
  `01.write-editor-implementation`. Covers the editor props, dispatch
  API, and the conventions for surfacing operations through the UI.

## Authoring flow

The editor spec only declares what the editor IS (document type, name,
status). `spec-generate` lays down a boilerplate component at
`<project>/editors/<editor>/editor.tsx` that renders the toolbar plus
a document-name input — nothing more. You **must** then edit that file
with `mastra_workspace_edit_file` to:

1. Import `actions` + the `useSelected<Model>Document` hook from
   `document-models/<model>` and dispatch the document's real
   operations from UI controls.
2. **Delete the boilerplate UI that doesn't apply.** The default file
   ships with a `handleSetName`/`setName` handler, the document-name
   input, the "Edit document name" label, and demo comments — strip
   anything the target document type doesn't actually use. Also remove
   imports that become unused after the strip (typically the
   `DocumentToolbar` is kept; the `setName`-related ones are not).

The final file should contain only the imports, handlers, and JSX that
the document type needs. Leftover boilerplate ships to preview and
muddles the UX — treat it as code you would not commit.

For file/image fields backed by an attachment ref, edit them with
`useEditorFileDrop` + `useAttachmentUpload` from
`@powerhousedao/reactor-browser` (see ED.01.4) — don't fall back to a bare
`URL` field.

## Gate before Phase 3

`spec-preview-show` against an editor that hasn't been customized
renders the generic name-only boilerplate. The preview "working" with
no further edits is a silent failure, not a success. Before preview,
confirm:
- `spec-generate` ran clean.
- `<project>/editors/<editor>/editor.tsx` contains operation dispatches
  for this document type (not just the default `handleSetName`).
- `<project>/editors/<editor>/` exists.

## Never

- Hand-edit `<project>/editors/<editor>/gen/` — regeneration overwrites.
- Restart the reactor after editing component source. Vite HMR is on.
