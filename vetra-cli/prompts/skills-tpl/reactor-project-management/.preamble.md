Reactor projects are the runtime that hosts document models, editors,
processors, and subgraphs during development. Each project is a
workspace directory with its own embedded Switchboard, Connect, and
preview drive, exposed on per-project ports.

## Before init

- **Always run `reactor-project-ls` and `reactor-project-ps` first.**
  A project with the requested name may already exist (possibly under a
  different working directory) and may be running. Re-initializing on
  top of an existing project is a common waste of a turn. If the
  project exists and is stopped, `reactor-project-start` it; if it
  exists and is running, do nothing.
- A single VetraAgent session can interact with one running project at
  a time. If a different project is running, stop it before starting
  another.

## Restart discipline

Do **not** call `reactor-project-restart` after spec changes, generated
code updates, or component-source edits. The spec watcher + Vite HMR
pick those up automatically. The one legitimate trigger for a restart:
`reactor-project-logs` shows the watcher *missed* an edit (no rebuild
log line after the change landed). Restarting otherwise wastes the
user's time and resets in-memory state.

## Endpoints

`reactor-project-start` output is the source of truth for the project's
ports and URLs (`mcp-server`, `vetra-studio`, `vetra-drive-url`,
`vetra-preview-drive-url`, `vetra-switchboard`). Re-read it rather than
assuming default ports.
